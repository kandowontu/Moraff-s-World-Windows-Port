# F8.EXE hall-of-fame static reconstruction

`F8.EXE` is the original hall-of-fame update module. The dungeon program
chains to it with a character summary in the temporary `NAME` file; it updates
the `F9.EXE` BSAVE table, displays the result, and chains back to `BEGIN`.

## Handoff record

`hall_of_fame_read_character` (`02DB`) performs one typed QuickBASIC `INPUT`
of eight values. The type list encoded at `02EF` is:

```text
single, single, single, string, single, single, single, string
```

The formatting path proves their roles as color enabled, player level, class,
name, pocket money, bank money, dungeon level, and killer/status text. Pocket
and bank money are combined for the displayed MONEY column. Class value 1 is
formatted as `FIGHTER`; every other accepted original value is formatted as
`WIZARD`. An empty killer string is changed to `STILL ALIVE`.

Names longer than 20 characters are represented by a 17-character prefix and
`...` (`0386`-`03AD`). Numeric fields are converted and right-aligned through
`hall_of_fame_right_align_number` (`045C`). The helper's exact QuickBASIC
expression is `RIGHT$(SPACE$(30) + STR$(value), width)`. The resulting record
is a fixed-width 80-column row matching the headings embedded at `2068` and
`20BA`.

## Persistent table

`hall_of_fame_load_table` (`01CC`) uses QuickBASIC `BLOAD` with an explicit
DS:`1856` destination to load `F9.EXE`, then reconstructs ten 80-character
records from its memory image. Consequently the segment and offset words in
the BSAVE header are informational and must not be used to reject an otherwise
valid table. The inverse
operation in `hall_of_fame_save_table` (`0230`) pads each record to 80
characters, writes it back into the image, and calls QuickBASIC `BSAVE` for
the same file. The remaining BSAVE payload bytes are preserved as part of the
resource rather than interpreted as executable code.

`hall_of_fame_sort_entries` (`00E9`) repeatedly compares adjacent records and
swaps them until a complete pass makes no swap. The comparison is based on
the fixed-width numeric prefix used for player level, with the subsequent
fixed fields acting as stable text content. The main routine conditionally
inserts the newly formatted record, sorts, draws, saves, and then executes
`CHAIN "BEGIN"` (`0030`-`00E6`).

## Display behavior

`hall_of_fame_draw_table` (`0498`) prints the heading, divider, and ten rows,
then a compact list containing the first five characters of every entry. It
waits for a nonempty key before returning.

`hall_of_fame_advance_row_color` (`0570`) is a no-op in monochrome mode. In
color mode it increments its counter, wraps a value above 5 to zero, and
applies `9 + counter`, producing the repeating call sequence
`10, 11, 12, 13, 14, 9`. This is deterministic row coloring, not random
selection.

The native implementation must keep this update path separate from normal
character saves: `NAME` is a transient inter-module record, while `F9.EXE` is
the persistent ten-entry hall-of-fame BSAVE image.
